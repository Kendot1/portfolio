# Design direction

## Diagnosis

The working tree already had source-backed case studies, theme persistence, a compact introduction, and a useful starting console. Preserve these rather than replacing the app. Defects found in the running site: project filters changed their counter but not their articles; missing project-art positioning let a fill image escape its container; the portrait requested a nonexistent file; artwork links overrode visible text with mismatched accessible names; console tests used an outdated region name. Secondary text was unnecessarily small.

## Thesis

A compact engineering notebook: identity first, project evidence second, then a local bench where visitors can inspect how data becomes a model input. Foodcast's shifted time-series features are the original identity anchor, not an invented AI persona. The console's small signal changes shape while resolving a local command; the feature lab makes the rule tangible with editable synthetic observations.

## Tokens and composition

- Paper #f3f7f7, inset #e5eeee, ink #152a31, muted #53696e, teal #1e7168, line #cedddb. Dark equivalents live in globals.css.
- Georgia for the name and interaction titles; Segoe UI for reading; system monospace only for commands and small structural details. No remote font requests.
- 1040px maximum shell; stacked project rows pair source artwork or a labeled system diagram with explanation. Mobile collapses to one column.
- Compact grouped navigation; numbered section headings; clear professional links. The console is linked in navigation and the introduction and follows selected work.
- No scroll-reveal dependency, fake telemetry, fabricated model output, or copied reference interaction.

## Reference and skill review

Bryl Lim's live page was requested at 1440px and 390px in Chrome. Both browser visits encountered a browser-check interstitial; the archive recovery script found no copy. A separate web extraction returned the reference's actual identity-first introduction, numbered section rhythm, stack, and GitHub section. Exact desktop/mobile visual parity therefore could not be established.

UI/UX Pro Max's required design-system and Next.js/UX searches were run. The first design-system result was misrouted to FAQ/documentation; the narrower retry suggested brutalism and scroll storytelling. Neither fits this brief. Reject their presets, handwritten fonts, purple palette, and scroll effects. Retain the applicable keyboard semantics, 44px interactive controls, contrast, responsive image containment, and reduced-motion guidance. The explicit reference and verified project content take priority.
